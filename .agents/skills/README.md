# Registered Skills

Skills are references subordinate to `.agents/WORKFLOW.md`, `.agents/RULES.md` and `.agents/CODING_STANDARDS.md`. A skill never prevails over the repo's local standard.

## Main dependency: autoskills

**autoskills** (`midudev/autoskills`) scans the repository, detects the real stack and automatically resolves the best skills from the audited registry. It is the main way for every repo to get the right skills without manual configuration.

| Aspect | Detail |
| --- | --- |
| Command | `npx autoskills` (at the repo root) |
| Requirement | Node >= 22 |
| Detection | Scans `package.json`, Gradle files and configs to detect technologies |
| Preview without installing | `npx autoskills --dry-run` |
| Skip confirmation | `npx autoskills -y` |
| Destination | `.agents/skills/` (universal fallback) or `.claude/skills/` (if Claude Code is detected). In this harness the canonical layout is `.agents/skills/` |
| Registry | Installs only skills from the maintainers' curated registry; verifies each file against a SHA-256 manifest |
| Lockfile | Writes `skills-lock.json` at the repo root with the installed source and the bundle hash |

### Recommended flow

1. `npx autoskills --dry-run` to review which skills it detects for the repo stack.
2. `npx autoskills -y` to install.
3. Check `skills-lock.json` and list the skills in the table below (source and date).
4. In every task, validate the skill is compatible with the real stack and the local standard.

### Usage rules

- Generic skill examples (npm/npx/pnpm/yarn, frameworks from other versions) are always adapted to the baseline declared in `.agents/AGENTS.md` and the conventions of `.agents/CODING_STANDARDS.md`.
- If a skill contradicts `.agents/RULES.md`, `.agents/CODING_STANDARDS.md` or `.agents/DESIGN.md`, the local standard prevails.
- Do not install skills that assume stacks, versions or tools that do not exist in the repo.

## Manual additions (optional)

Skills not covered by the autoskills registry are added with the official skills CLI (`skills.sh` / `npx skills`):

1. `npx skills find <query>`
2. `npx skills add <owner/repo> --list`
3. Read `SKILL.md` and scripts.
4. Audit commands, network, filesystem and secrets.
5. Ask for approval before installing.
6. Register source and date.

## Onboarding process

1. `npx autoskills --dry-run` (or `npx skills find <query>` for manual searches).
2. Review the detected list against the real repo stack.
3. Install with `npx autoskills -y` (or `npx skills add <owner/repo> --list` for manual ones).
4. Read `SKILL.md` and audit scripts (commands, network, filesystem, secrets).
5. Ask for user approval before installing.
6. Register source and date in the table.

## Local additions (preserved on update)

`npx autoskills --dry-run` (07/10/2026) only detects **Bash** in this repo and offers
`bash-defensive-patterns`, `frontend-design`, `accessibility` and `seo`: none of them fits a
C++/WASM game engine, so the registry was searched by hand (`npx skills find`) and the four
below were installed with `npx skills add <owner/repo@skill> -a universal -y` (destination
`.agents/skills/`, lockfile `skills-lock.json`).

| Skill | Source | Use | Date |
| --- | --- | --- | --- |
| `wasm-emscripten` | mohitmishra786/low-level-dev-skills | emcc, Asyncify, modelo de memoria WASM, wasm-opt: el stack real del port | 2026-10-07 |
| `cpp-coding-standards` | affaan-m/ecc | C++ Core Guidelines para escribir y revisar el motor; **subordinado** a `CODING_STANDARDS.md` | 2026-10-07 |
| `cpp-testing` | affaan-m/ecc | Solo referencia: el repo no tiene framework de tests C++ (verificación = build servida + log del jugador) | 2026-10-07 |
| `python-design-patterns` | wshobson/agents | `gta_vc_browser/tools/*.py`; es la más prescindible, se quita con `npx skills remove python-design-patterns` | 2026-10-07 |

Auditoría hecha antes de registrarlas: las cuatro son documentación (un `SKILL.md` y, dos
de ellas, referencias `.md`), **sin scripts ni ejecutables** y sin comandos de red, `curl`
o instalación. Los cuatro ficheros son LF salvo `python-design-patterns` (CRLF), que no se
edita. `wasm-emscripten` llega también en CRLF: los ficheros descargados se dejan tal como
los publica su origen.

Desajuste del harness que no hay que perseguir: el CLI escribe el lock en la **raíz del
repo** (`skills-lock.json`, que es lo que dicen esta página y `autoskills`) y
`scripts/verify.mjs` lo busca en `.agents/skills/skills-lock.json`, así que avisa «no
skills-lock.json» aunque las skills estén instaladas. El lock se deja donde lo escribió el
CLI; no se duplica el fichero.
